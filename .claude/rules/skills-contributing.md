# Skill authoring boundary

Use [the contribution contract](../../CONTRIBUTING.md) to review the gap before a new
skill directory, and [the format contract](../../docs/skill-anatomy.md) to package it.
Extend the existing owner when its workflow already covers the intended decision.

Author decisions, failure cases and observable completion conditions in
[the maintainer's style](../../docs/walidforge-style.md). Preserve published identifiers,
current user scope and installed-project conventions. Supporting resources need a
concrete purpose and a discoverable link; do not add empty directories or copies of
shared manuals merely to make a skill look substantial.

Verify structure, routing and relevant scenarios separately. An unchanged case
schema or a passing lexical rank does not prove a model followed the instructions.
