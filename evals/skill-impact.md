# Record Evidence Behind Workflow Decisions

Use this ledger for significant accepted or rejected changes when real evidence is
available. A recorded decision should prevent repeat work without turning an old
model result into a universal rule.

| Date | Workflow/revision | Observed problem | Change considered | Actual evidence/environment | Decision and reason |
|---|---|---|---|---|---|

Do not invent rows, PR links or model measurements. State lexical routing, structural
validation and actual behavioral execution separately. A rejected proposal can be
reconsidered when constraints or evidence change; cite what changed.

Local authoring changes may be reviewed before a PR exists. Record their context and
outcome accurately instead of requiring a remote publication to preserve useful
reasoning. The full [evaluation contract](README.md) governs how results are reported.
