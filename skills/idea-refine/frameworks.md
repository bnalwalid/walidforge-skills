# Explore Alternatives That Change the Decision

Read this when the concept needs expansion before convergence. Use one approach
that fits the unknown; these are reasoning aids, not a mandatory workshop.

## Outcome reframing

Describe the user decision or task without naming the proposed solution. Ask what
would improve if no new software were built. Compare workflow changes, reuse and
new implementation against the same constraints.

## Constraint variation

Hold the outcome fixed and vary one constraint: no network, no dedicated operator,
existing devices only or a shorter first release. The useful result identifies
which assumption makes the current design expensive or fragile.

## Failure inversion

Imagine the first useful outcome failed. Identify a plausible cause: users cannot
supply required inputs, an integration cannot be trusted or maintenance exceeds the
team's capacity. Choose a small observation that could disprove that assumption.

## Boundary reduction

Remove an audience, integration or automation step and ask whether the first user
still obtains value. Keep exclusions explicit. A reduced feature is useful only if
its remaining path delivers a real outcome, not merely a demo screen.

## Convergence

Compare credible options by outcome, evidence, implementation/operating cost and
failure risk. Recommend a direction with reasons, untested assumptions and the next
validation decision. Do not imply that a framework scored the idea scientifically.
